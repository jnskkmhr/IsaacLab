# G1 locomotion task on moving patch MPM

This standalone IsaacLab task places all robots on **one background terrain generated by `isaaclab.terrains`**. Each robot has its own bounded set of moving MPM particles and independent physics world. Particles that remain in simulated terrain retain their deformation and velocity. Recycled particles sample the shared terrain height and become fresh sand. Returning to a place does **not** restore previous tracks.

## Resume curriculum progress

The moving-patch and mixed-terrain tasks use `agents/compositional_ppo_cfg.py`: independent
MLP actor and critic heads with the existing observation order, PPO settings, and symmetry augmentation.
The root `pyproject.toml` and `uv.lock` pin `compositional-rsl-rl` to commit `5ca12657`.
Run `uv sync --locked --extra rsl-rl` after updating this checkout.

Resume a compositional checkpoint or an existing ordinary RSL-RL MLP checkpoint using the usual entrypoint:

```bash
uv run --with wandb isaaclab train --rl_library rsl_rl \
  --task IsaacContrib-Velocity-G1-29dof-MPM-MovingPatch-MixedTerrain \
  --num_envs 64 --checkpoint /path/to/model_10000.pt --resume_optimizer_state
```

Checkpoints store the exact `common_step_counter` alongside the policy. Loading restores that
counter; step-based curricula use it at their next normal update. Use
`--no-resume_optimizer_state` to restore the counter while starting a fresh policy optimizer.
Optimizer restoration is enabled by default.
`env_interface = EnvInterfaceCfg()` also checkpoints per-rank terrain levels, column assignments,
terrain origin grid/seed, rigid/MPM membership when present, and the physics step counter.
Terrain restoration is disabled by default, so playback and finetuning keep the destination terrain.
For an exact terrain resume, append `agent.env_interface.restore_terrain=true`. This requires the
same world size, environments per rank, terrain configuration, and rigid/MPM assignments.
Restoration resets fresh episodes on the saved terrain without advancing terrain levels during
that reset. Episode motion, solver history, and random-number-generator state are not restored.

Use `agent.env_interface=null` to disable terrain checkpointing entirely. Checkpoints without terrain
state leave terrain assignments untouched and do not reset the environment. The training counter
is still restored/estimated independently.

Older checkpoints without the counter estimate progress as
`(iteration + 1) * num_steps_per_env` and warn. This assumes the same rollout length and no
previous curriculum restart. Ordinary RSL-RL checkpoints load directly when they contain separate
`actor_state_dict` and `critic_state_dict` entries matching these independent MLP heads. Keep the
observation/action order, activation, and normalization settings identical to the source policy.
The older combined `model_state_dict` format is not supported.

# Moving patch terrain with mixed rigid ground

The mixed task uses the terrain generation and fixed environment allocation from
run `k9mk7koh`. It requires an even `num_envs >= 2`: the first half of environments
use MPM and the second half use rigid ground. With 64 environments, IDs 0–31 use
MPM and IDs 32–63 use rigid ground. Membership stays fixed across episode resets.

The standard generator creates one terrain grid. Its first half of columns support
MPM; the remaining columns support rigid ground. With the default five columns,
MPM receives two columns and rigid ground receives three, so the groups see different
terrain types. Geometry is not duplicated. The MPM support surface is lowered by the
particle-bed depth; the rigid walking surface stays at its generated height.
The rough-terrain wave amplitude range is 0.1–0.4 m. Updated reward weights are retained
for comparison against the earlier run.

## Roll/pitch observation bias in moving-patch training

The shared actor `PolicyCfg` uses `mdp.bias_projected_gravity`, with zero bias by
default. Moving-patch and mixed-terrain training share the bias curriculum.
Each environment samples
independent, uniform roll and pitch offsets when it resets and keeps them for that
episode. The offsets rotate the observed gravity direction; they do not change the
robot's physical orientation. The critic and both Play configurations remain
clean. Use the Play configuration with built-in projected gravity for policy export.

`G1CurriculumCfg` in `env_cfg/curriculum_cfg.py` ramps each sampling range
from `(0.0, 0.0)` to `(-math.radians(5.0), math.radians(5.0))` over 120,000 control
steps (5,000 PPO iterations at 24 steps per iteration). Edit `final_value` and
`end_step` in `gravity_roll_bias` and `gravity_pitch_bias` to change these defaults.
The curriculum uses `mdp.modify_term_cfg` with `mdp.linear_ramp`; updated ranges
apply only when an environment next resets. This schedule uses the environment's
`common_step_counter`, not an inferred iteration number from a checkpoint.

The observation lives in `PolicyCfg` in `env_cfg/observation_cfg.py`:

```python
projected_gravity = ObsTerm(
    func=mdp.bias_projected_gravity,
    mirror=mirror_vec3,
    params={
        "roll_bias_range": (0.0, 0.0),
        "pitch_bias_range": (0.0, 0.0),
        "roll_noise_std": 0.0,
        "pitch_noise_std": 0.0,
    },
)
```

All angle parameters are **radians**. Optional `roll_noise_std` and `pitch_noise_std`
add independent Gaussian angular noise on each observation evaluation; both default
to zero. This replaces the mixed actor's previous Cartesian gravity-vector noise,
so the gravity vector remains unit length. The error rotation uses the robot's local
root axes: `q_observed = q_root * q_error`.

This is tolerance training for orientation error, not a reproduction of Unitree's
IMU estimator. Because the randomness is inside the observation term, setting
`enable_corruption=False` alone does not disable it; use `mdp.projected_gravity`
with empty parameters for clean evaluation, as the mixed-terrain Play config does.
